# QML Storybook

Storybook открывает отдельное окно Quickshell и показывает настоящий `ui/Dashboard.qml` вместе с его `ContextView`, `ContextLane` и `ContextCard`. Все события в нём вымышлены. Галерея не читает `~/.codex`, не запускает блокировку или PAM и не меняет конфигурацию Omarchy.

Из корня проекта:

```bash
qs -p storybook.qml
```

Левая колонка выбирает сценарий, ширину 820/1360/1680 px, светлую или тёмную палитру, режим заставки или заблокированного экрана. Наложение пароля — только макет, без поля ввода. Сверху находятся пуск/пауза, один шаг, сброс, страницы и три скорости событий. При паузе останавливаются подача событий и дрейф; шаг применяет одно следующее событие с push-анимацией и коротким дрейфом, затем снова останавливает движение. Повторное обновление ID заменяет карточку. После последнего шага пуск/шаг начинают последовательность заново.

Сценарии охватывают поиск, достоверно пустой состав, 1/2/3/4/7 чатов, ожидание ответа, неизвестный источник, потерю связи, ошибку команды, завершение и поток новых блоков. Светлая/тёмная палитры — синтетические проверочные варианты; установленный плагин продолжает брать цвета из выбранной темы Omarchy.

Воспроизводимые offscreen-кадры и машинная проверка состояний:

```bash
python3 check_storybook.py --out /tmp/endless-session-storybook-check
```

Команда запускает галерею в изолированном временном HOME и сохраняет синтетические PNG вместе с `report.json`. Она проверяет состав и страницы, но не заменяет визуальную оценку движения, системную проверку блокировки или человеческую приёмку. Для отдельного кадра поддержаны переменные `OC_STORYBOOK_STORY`, `OC_STORYBOOK_THEME=light`, `OC_STORYBOOK_WIDTH=820|1360|1680`, `OC_STORYBOOK_MODE=locked`, `OC_STORYBOOK_STEPS`, `OC_STORYBOOK_PAGE`, `OC_STORYBOOK_PASSWORD=1` и `OC_STORYBOOK_CAPTURE=<абсолютный-путь.png>`.
